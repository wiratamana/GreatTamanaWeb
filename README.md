# Wira Tamana: portfolio website

Static site for GitHub Pages. Plain HTML, CSS and JavaScript. No framework, no build step, no network calls.
English now, Japanese later: every text is in a language file, nothing is hard coded in the pages.

Open `index.html` in a browser (works from a plain folder too), or push to GitHub Pages.

```
https://wiratamana.github.io/GreatTamanaWeb/      (project site: all links are relative)
```

## 2. Architecture (why it is easy to change)

```
index.html ... *.html        only structure. No text. Texts are keys: data-i18n="home.hero.h1"
css/
  tokens.css                 colours, fonts, spacing. Change the whole look here (one accent colour)
  base.css                   reset, typography, page shell, header, footer
  components.css             every component: card, stat, metric, flow, layers, bars, callout, fig ...
js/
  core/loader.js             THE only script a page includes. Chooses language, loads everything else
  core/i18n.js               translation engine: GTW.t("key"), data-i18n, fallback to English
  core/repeat.js             data-repeat: builds cards/rows/steps from the text files
  core/media.js              figures, screenshots, video and the placeholders
  core/ui.js                 lightbox, reveal on scroll, bars, table of contents
  core/layout.js             SAME header + footer on every page (from js/data/site.js)
  core/boot.js               starts it all in the right order
  data/site.js               EDIT FIRST: name, contacts, repo links, navigation
  data/cases.js              index of the 30 case studies (language neutral)
  data/gallery.js            gallery list        data/apptools.js   the 173 app tools
  components/case-card.js    the one case card used everywhere
  pages/*.js                 small page specific code (journal filter, case renderer ...)
i18n/
  en/<bundle>.js             English texts (the source of truth)
  ja/<bundle>.js             Japanese texts (empty now, falls back to English)
assets/
  img/ + img/thumb/          WebP images (made by tools/build_images.py)
  media/                     screenshots and videos you add later (see section 5)
tools/                       build_images.py, i18n_check.py, list_slots.py, smoke_test.py
```

A page declares what it needs on its `<html>` tag, nothing else:

```html
<html lang="en" data-page="home" data-bundles="common,home,cases"
      data-scripts="data/cases,components/case-card,pages/home"
      data-title="home.title" data-desc="home.desc">
```

### Unified UI
Every page is built from the same components in `css/components.css`. Header and footer are generated by
`js/core/layout.js`. A new page = copy any page, change the `<html>` attributes and the keys. Do not add per-page CSS.

### `data-repeat`: lists come from the text files
```html
<div class="grid g3" data-repeat="home.can" data-tpl="card"></div>
```
renders one card per `home.can.1.*`, `home.can.2.*` ... that exists. To add a card, add keys
`home.can.7.t` and `home.can.7.d`. Templates: `card stat metric dl step layer li chip tr ev acc fig`
(fields are listed at the top of `js/core/repeat.js`).

## 3. Japanese translation

1. Language switch is in the header (EN / 日本語). The choice is stored in `localStorage`. `?lang=ja` forces it.
2. Open `i18n/en/home.js` and `i18n/ja/home.js`. Copy keys you translate into the Japanese file:
   ```js
   GTW.i18n.add("ja", {
     "home.hero.h1": "ゲームエンジン技術をつくっています。",
   });
   ```
3. Missing keys fall back to English. A blue note appears at the top while a page is only partly translated.
4. Keep these keys identical in both languages (links, icons, numbers inside bars): `.href .img .ic .tagc .hl .slot .kind .ratio .thumb .tone .b .a .u`.
   Numbers and product names that do not change (for example `"home.stats.1.v": "139k"`) still need to be copied, or the note stays on.
5. Check progress:
   ```
   python tools/i18n_check.py          # missing keys per file, typos, unused keys
   python tools/i18n_check.py --stub   # writes i18n/ja/*.todo.txt: key <TAB> English text, for a translator
   ```
Done now: `common.js` and `home.js` are translated, as a working example.
Bundles to translate next, in value order: `cases-perf`, `cases-cloud`, `engine`, `animation`, `app`, `about`, `workflow`, `rendering`, `tools`, `clouds`, `cases-anim`, `cases-look`, `cases-tools`, `journal`, `gallery`, `slots`.

## 4. Add or change content

* **New case study**: add one entry to `js/data/cases.js`, then its texts to the right `i18n/en/cases-*.js`
  (`case.<id>.title .summary .problem .cause .fix .result` + optional `.method .limits .hl .f1 .m.1.v .bars.*`).
  Run `python tools/i18n_check.py` to see what you forgot. Every case uses the same template.
* **New image**: put the PNG/JPG in `assets/drop-in/`, run `python tools/build_images.py --drop-in`
  (needs `pip install pillow`), then use `<figure data-img="name" data-cap="key">`.
  Only publish your own images. Never third-party reference pictures.
* **New page**: copy a page, add it to `nav` in `js/data/site.js`.
* **Contacts, repo links**: `js/data/site.js`. Set `showPlaceholders: false` right before publishing.
  Set `repos.engine.public: true` only if the repository is really public. Otherwise the site says "source on request".

## 5. Screenshots, WebP loops and videos: placeholders

Every dashed box on the site is a **slot**. Put a file with the slot name into `assets/media/` and it replaces the box
automatically. No HTML to edit.

| Slot kind | File names it looks for | Use |
|---|---|---|
| `image` | `<slot>.webp` `.png` `.jpg` `.jpeg` | static screenshot |
| `webp` | `<slot>.webp` | short animated loop (3 to 6 s) |
| `video` | `<slot>.mp4` `.webm` | demo video |

```
python tools/list_slots.py      # which slots are empty, what to capture, which file name to use
```
The capture hint for every slot is in `i18n/en/slots.js`.
Safety: no company names, no chat sessions, no file paths with user names, no corporate screenshots.

## 6. Check before you publish

```
python tools/i18n_check.py      # keys: 0 problems expected
python tools/smoke_test.py      # opens every page in headless Edge/Chrome, EN + JA, prints console errors
python tools/smoke_test.py --shots out   # also saves screenshots
```
Add `?static=1` to a URL to turn animations off.

## 8. Honesty rules used on this site

* Every number comes from the source code, git history or the R&D notes, with the file or commit named.
* Every case study has a **Not proven / limits** box. Failures and missed targets are published.
* All timings: one laptop with an Intel Iris Xe iGPU. The site says so.
* Most engine code is written by AI agents under my specs and review. The site says so (see How I work).
* Third-party content is credited (libraries on the engine page, MMD assets on the animation page).
  The old draft used crops of Unreal and other third-party screenshots. They were removed.

## 9. Things to decide or fix before publishing

* `js/data/site.js`: email, LinkedIn, CV, repository visibility.
* Add your Japanese level to `about.html` (e.g. a row in `about.site` or a new `about.lang` block).
* **Privacy**: the engine repository history has commits authored with a work-PC identity and an employer email domain
  (about 1,037 commits). If the repository is public, consider rewriting the author with a `.mailmap` or `git filter-repo`.
  This site never shows that identity.
* The MMD test character is a third-party asset. If you want zero risk, replace the Bone Viewer and editor
  screenshots (`phys-*`) with ones that use your own model.
* Re-check numbers when the engine changes. They are a snapshot of 2026-11-13.
